# Mr Robot (Red Team) Tasks

## Install Mythic C2 Framework

Mythic is an open-source Command and Control (C2) framework designed for red team operations and adversary emulation. It allows operators to interact with compromised systems in a stealthy and customizable manner. Originally developed by Cody Thomas (a.k.a. its_a_feature_), Mythic supports multiple agents and payloads that can be tailored to specific operational needs. It provides a robust and modular architecture that includes a web-based interface for managing tasks, communications, and agent development, making it highly flexible for offensive security teams. Mythic is especially valued for its cross-platform support and its ability to integrate with other red teaming tools.

**Supported C2 Profiles**

[**HTTP/HTTPS Profile**](https://github.com/MythicC2Profiles/http)

The HTTP profile calls back to the Mythic server over the basic, non-dynamic profile. When selecting options to be stamped into Apollo at compile time, all options are respected with the exception of those parameters relating to GET requests.

[**SMB Profile**](https://github.com/MythicC2Profiles/smb)

Establish communications over SMB named pipes. By default, the named pipe name will be a randomly generated GUID.

[**TCP Profile**](https://github.com/MythicC2Profiles/tcp)

Establish communications over a specified network socket. Note: If unelevated, the user may receive a prompt to allow communications from the binary to occur over the network.

## Detection Solution

The SPL below will detect a file executing from within the Windows\Temp directory.

```go
source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| table _time Computer process_name CommandLine ParentImage
| where like(CommandLine, "%\\Windows\\Temp\\%")

```

### Explanation:

- `source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"`: Targets the Sysmon event log, specifically event code 1 (process creation).
- `EventCode=1`: Filters for Sysmon process creation events.
- `table _time Computer process_name CommandLine ParentImage`: Selects and displays relevant fields like timestamp, computer name, process name, command line, and parent image for better context.
- `where like(CommandLine, "%\\Windows\\Temp\\%")`: Filters results where the process command line contains `\Windows\Temp`.

This query will help detect any executables running from the `\Windows\Temp` directory and present relevant details for further analysis.

**Now we should look for persistence mechanisms.**

Remember to reset the time picker to extend the search window to more than 20 seconds.

This SPL query below captures a broad set of persistence mechanisms, including registry modifications, scheduled tasks, WMI event subscriptions, and file creation in Startup folders. By reviewing these events in combination, we can effectively identify persistence techniques being used on the system.

```go
source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" (
(EventCode=13 AND (
TargetObject="*\\Software\\Microsoft\\Windows\\CurrentVersion\\Run*" OR
TargetObject="*\\Software\\Microsoft\\Windows\\CurrentVersion\\RunOnce*" OR
TargetObject="*\\Software\\Microsoft\\Windows\\CurrentVersion\\Policies\\Explorer\\Run*" OR
TargetObject="*\\Software\\Microsoft\\Windows\\CurrentVersion\\RunServices*" OR
TargetObject="*\\Software\\Microsoft\\Windows\\CurrentVersion\\RunServicesOnce*"))
OR
(EventCode=1 AND (Image="*schtasks.exe" OR CommandLine="schtasks /create*"))
OR
(EventCode=1 AND (Image="*powershell.exe" AND CommandLine="New-ScheduledTask"))
OR
(EventCode=19 AND (Consumer="*" OR Query="*"))
OR
(EventCode=11 AND (
TargetFilename="**\\AppData\\Roaming\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\**" OR
TargetFilename="**\\ProgramData\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\*"))
)
| table _time EventCode Computer User TargetObject TargetFilename Image CommandLine ProcessId ParentImage ParentCommandLine
```

Explanation:

1. **Registry Persistence (Sysmon Event ID 13)**:

The query searches for modifications to registry keys commonly used for persistence:

- `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`
- `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunOnce`
- `HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run`
- Other `RunServices` and `RunServicesOnce` keys.

These keys are used by attackers to ensure that malware or persistence payloads are executed during user logon or system boot.

2. **Scheduled Tasks (Sysmon Event ID 1)**:

Scheduled tasks are a common persistence mechanism. The query looks for commands used to create scheduled tasks (`schtasks.exe` or `New-ScheduledTask` via PowerShell):

- `schtasks /create` (task creation)
- `powershell New-ScheduledTask`

3. **WMI Event Subscription (Sysmon Event ID 19)**:

WMI event subscriptions are a stealthy persistence technique. The query captures the creation of WMI subscriptions:

- **Consumer** or **Query** fields capture the WMI actions that could trigger persistence.

4. **File Creation in Startup Folders (Sysmon Event ID 11)**:

Files placed in **Startup folders** will execute on system startup. The query monitors file creation in:

- User-specific Startup folder (`AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup`)
- System-wide Startup folder (`ProgramData\Microsoft\Windows\Start Menu\Programs\Startup`)

As we can see above, the Startup folder was used as a persistence mechanism.
